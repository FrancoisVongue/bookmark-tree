## Оговорки

- ⚠️ Отмена возвращает библиотеку к состоянию до твоего действия. Вкладки, открытые после него, остаются, но их узлы встают в конец дерева.
- ⚠️ Отмена не открывает заново вкладки, закрытые удалением: узел возвращается спящим.
- ⚠️ После перезапуска браузера вкладка находит свой узел по адресу (Chrome выдаёт вкладкам новые номера). Два спящих узла с одинаковым адресом могут поменяться вкладками.
- Средний клик по живому узлу закрывает вкладку (узел засыпает); по спящему — убирает его из дерева (с плашкой «Отменить»). Открыть в фоне — через меню.

  - страница, на которой ты побывал (те же полторы секунды, что в журнале), сама уходит из плана и оказывается в журнале; пролистанная мимо — остаётся. Страницы, на которой ты сейчас, в ленте нет;
  - план — часть библиотеки (`library.plan`): переживает перезапуск, попадает в бэкапы, синхронизируется обоими каналами. При слиянии берётся целиком, как таблица деревьев: если план меняли на двух компьютерах сразу, побеждает один;
  - удалённый узел из плана выпадает сам; восстановленный из корзины — возвращается на своё место;
  - проверено юнит-тестами и сценарием в Chromium (`test/browser/plan.mjs`), скриншоты в светлой и тёмной теме смотрел. В настоящей боковой панели не проверялось.
  - ⚠️ с клавиатуры записи ленты недоступны (ни фокуса, ни Enter); у журнала снизу фокус есть.
- 💬 **О4. Домашний адрес по умолчанию.** Предложение: каждый узел сам запоминает первый адрес; кнопка «домой» появляется, когда ушёл; при закрытии вкладки на этот адрес возвращается только закреплённый вручную. Ждёт ответа.
- ⏸ **О1. Живое поддерево** — отложено: должно работать само, а не отдельной фичей; обдумать отдельно.
- [ ] **Даты у узлов** (после О3): у узла может быть дата-время напоминания; такие сами попадают в план на сегодня. Просроченные не копятся в плане, а лежат в отдельном легкодоступном месте, чтобы не перегружать.

## Быстрый канал: как устроен (2026-11-13)

- В хранилище Chrome (`chrome.storage.sync`, около 100 КБ) лежит вся библиотека целиком, сжатая. Токен и репозиторий для этого не нужны.
- Не влезает — лежит только свежая часть: узлы, которые открывали или закрывали последними, вместе с папками над ними. Остальное остаётся на компьютерах, где оно есть. Об этом говорит жёлтая полоска внизу панели; её можно закрыть.
- Чего в снимке нет, о том он молчит: узел удаляется на другом компьютере, только если удаление названо явно. Через канал ничего нельзя потерять; худший случай — что-то не показалось на другом компьютере.
- Узлы сгруппированы по месяцу последнего использования; месяц, который никто не трогал, заново не пишется.
- Сколько влезает: твоя библиотека (125 узлов) занимает 16,6 КБ из 90; 2000 страниц со случайными адресами по 90 символов — влезло 1110.
- Новые id короткие (12 знаков вместо 36); старые остаются как есть.
- Оговорки: удаление дерева доезжает, только когда у компьютеров общее прошлое; при первой встрече двух библиотек расположение общих узлов берётся с той стороны, что написала последней. Одновременная запись с двух компьютеров разобрана (изменения обоих сохраняются), но только для одного шага назад.
- GitHub остаётся для истории версий и как полный дом для того, что не влезло.
